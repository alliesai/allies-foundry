Reviewed implementation plan

Let long Hermes streams finish

FND-008.5 removes an accidental 512-frame ceiling from the incremental runtime parser. A valid terminal event must remain reachable after a long answer has streamed, while byte, text, identity, tool, and timeout safeguards stay in force.

Observed failure

The terminal frame was rejected

Sandy emitted 510 ordered message.delta events. The expected terminal event was raw frame 513, so the parser returned malformed_response.

Evidence: .agent/fnd008-sandy-greg-r2-first-streams.json

The smallest safe change

Keep processing the incremental response one bounded SSE frame at a time. Remove only the universal raw-event rejection from that path. The existing total stream-byte limit, per-frame limit, bounded line reads, value-size checks, idle socket timeout, and configured overall stream_timeout continue to bound the stream.

Keep MAX_EVENTS for the existing small history, transcript, and marker collections. Add an explicit MAX_BUFFERED_EVENTS = 65,536 guard for the legacy whole-result parser, which is the only path that stores all parsed events.

Protected contract

Every accepted delta stays visible

No coalescing or dropping of assistant deltas is part of this fix. Tool starts and completions remain ordered and sanitized.

The event path stays the same

The parser changes its raw-frame safety boundary. The product event vocabulary and ownership boundaries do not change.

Implementation phases

Phase 1

Reproduce and fix

  • Add a deterministic stream with 510 deltas, lifecycle frames, and a valid terminal sequence.
  • Keep the shared collection limit, add the buffered-list guard, and remove only the incremental raw-frame rejection.
  • Keep the raw ordinal for deterministic activity IDs without using it as a rejection condition.
  • Prove malformed, truncated, identity-changing, oversized, invalid UTF-8, and keepalive-only timeout streams still fail.

Phase 2

Publish and prove live

  • Run backend and runtime validation in their separate uv environments.
  • Publish an immutable runtime image digest.
  • Run Sandy's detailed 12-week fitness-program prompt until a response exceeds 512 raw frames, then retain sanitized text plus terminal evidence.
  • Verify authoritative cleanup of Machines, Volumes, apps, secrets, credentials, and proof records.

Rollback

Revert the runtime parser commit and use the last immutable runtime image digest. Do not change Hermes data or the durable Foundry schema.

Risks that stay visible

  • Removing the incremental raw-frame cap is safe only because total bytes, frame bytes, bounded reads, value sizes, idle reads, and the configured overall stream deadline remain enforced.
  • Many deltas still create many Foundry writes. The 4 MiB stream bound remains the current contract; checkpointing or event compaction needs a separate product decision if measurements show storage pressure.
  • Live staging uses real provider and Fly resources, so cleanup is part of the acceptance proof, not an afterthought.
